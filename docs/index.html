The dataset

DataCo Supply Chain's Late_delivery_risk

DataCo Smart Supply Chain is a public, widely reused benchmark of roughly 180,000 orders. Its Late_delivery_risk label is defined by comparing two of its own columns: how long shipping was scheduled to take, against how long it actually took. A model that sees both is not forecasting lateness — it is checking the label's own arithmetic.

The gap a single-column check misses

Neither column is suspicious alone

Scored one at a time, against the share of the label each column can explain on its own (0–1; this is the same scale bdp-model-gate's stock leak detector uses), both shipping-day columns sit well under its 0.80 flag threshold. Their difference — a line no model needs to learn — clears it by a wide margin.

Days for shipment (scheduled) + Days for shipping (real) together reach 0.948 of the target out-of-fold (100% of the whole model's 0.948), while no single one of them alone reaches 0.80 — check whether they are different views of the same post-outcome fact.
How it catches it

Pairs, scored honestly

01Candidate pairs — every pair (optionally triple) of numeric columns is a candidate, capped by individual power when there are too many to test exhaustively.
02Least squares, not a black box — a plain linear combination is fit per pair. The question is whether something this simple reconstructs the label, which is exactly what a careless join or feature-engineering step produces.
03Out-of-fold, never in-sample — each row is scored from a fit that never saw it (5-fold by default), so a flag reflects reusable signal, not a fit's freedom to find some line through the data.
04Deterministic folds — assigned by row content, not position, so permuting the validation set can't move a row into a different fold or change the verdict.
05Disjoint by design — a column target_leakage would already flag alone is dropped from the candidate pool, so every finding here is one that check could not have told you.
